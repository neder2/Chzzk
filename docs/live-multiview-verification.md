### 자동 숨김 수정 — 2026-09-06

실제 플레이어 CSS에서 `.pzp-pc__viewmode-button`은 기본 `opacity: 0`, `.pzp-pc--controls`일 때 `opacity: 1`인 것을 확인했어요. 멀티뷰 버튼에도 동일한 표시 상태를 적용하고, 숨김 중에는 포인터 입력·탭 초점·접근성 노출을 막았어요. 조작부를 숨겼을 때 버튼 투명도가 1로 남는 회귀 테스트의 실패를 먼저 확인한 뒤 수정 후 통과시켰어요. 숨김·표시 전환이 보조 방송을 재시작하지 않는 것도 확인했어요.

## 지연 시간 기준 보정 — 2026-09-06

기존 `seekable.end − currentTime`은 방송 조각 갱신 사이에 감소하고 갱신 때 뛰는 값이었어요. 보조 방송은 패키지 HLS 1.6.16의 공개 `latestLevelDetails.edge + age − currentTime`을 사용해 갱신 이후 경과 시간을 포함해요. 이전 이벤트의 재생 시각이 남을 수 있는 캐시된 지연값은 직접 사용하지 않아요.

메인은 네이티브 HLS 객체에 접근하지 않고 실제로 진행하는 탐색 범위 끝을 두 번 이상 관찰해요. 관측한 끝과 단조 시계의 경과 시간을 연결하며, 최근 관측 간격 3개만 보관해요. 소스 변경·시간 역행·불연속·오래 갱신되지 않은 경계는 다시 측정해요. 보조 방송도 실제 플레이리스트의 target duration을 기준으로 오래된 시간 정보의 외삽을 중단해요. 관측 간격에 기반한 제한이므로 특정 방송의 1초 조각을 고정하지 않아요.

새 저장값은 버전 2와 `live-edge-clock` 기준을 명시하고, 표시·수동 조절·복원에 같은 보정된 끝 시각을 사용해요. 기존 버전 1 저장값은 덮어쓰거나 임의 보정하지 않고 이전 기준임을 표시해 종전대로 복원해요. 사용자가 다시 조절하면 새 기준으로 저장해요. 방송 정보가 준비되기 전에는 새 기준의 양수 딜레이 복원을 기다려요.

결정적인 시계 테스트에서 조각 갱신 전후의 일정한 3초 지연, 실제 일시정지 중 지연 증가, 오래된 정보의 측정 중단, 메인의 초기 측정 대기, 소스 전환, 이전 저장값 호환과 새 기준 저장·복원을 확인했어요. 값은 송출 화면까지의 절대 실측이 아닌 라이브 기준 추정치로 표시해요.

로컬 검증 화면에서 실제 공개 방송 `b68af124ae2f1743a1dcbf5e2ab41e0b`의 기존 계산값은 비교한 두 시점에서 약 3.45초와 2.75초였지만 보정 표시는 두 번 모두 3.7초였어요. 1초 늦추기 후 저장·추정값이 4.7초로 표시됐고 새로고침 후에도 저장 4.7초·추정 4.7초·적용 완료를 확인했어요. 메인 역할의 실제 스트림에도 관측 기반 추정값이 표시됐어요. 이 결과는 테스트용 네이티브 영역과 저장소를 사용한 검증이며 실제 치지직 확장 주입 상태의 검증과 구분해요.

## 박스 안 영상 위치 — 2026-09-06

영상 비율에 맞춰 남은 공간의 가운데로 고정하던 좌표 계산에 채널별 가로·세로 정렬값(0~1, 기본 0.5)을 적용했어요. 분할 트리와 영상 크기는 유지하고 여백 안에서만 이동해요. Alt + 드래그와 보조 설정의 위치 슬라이더를 제공하며, 드래그 미리보기는 저장 상태와 분리해 취소나 볼륨 변경으로 미완료 위치가 저장되지 않게 했어요. 놓은 위치는 기존 탭 세션에 보관하고 영구 딜레이 저장에는 영향을 주지 않아요.

회귀 테스트로 메인·보조의 수직·수평 이동, 경계 제한과 중앙 스냅, 미리보기와 확정 저장, Esc·포인터 취소·창 초점 이탈·기능 해제, 네이티브 클릭 방지, 위치 슬라이더와 볼륨 분리, 가운데 초기화, 잘못된 값과 이전 세션, 화면 크기 변경·새로고침·메인 교체의 위치 유지를 확인했어요. 전체 355개 테스트·린트·포맷 검사를 통과했어요.

로컬 검증 URL `http://127.0.0.1:18765/live/64a90ba95d1f9feb0a798a20bbf0f40c`에서 실제 포인터로 보조 박스의 가로 구분선을 내려 여백을 만들고, 세로 위치 슬라이더를 키보드 End로 100%에 맞췄어요. 영상 크기는 약 283.33×159.36px로 유지된 채 아래 경계(y≈420)에 붙었고, 새로고침 후에도 같은 좌표로 복원됐어요. 다크·기본 화면과 라이트·넓은 화면에서 렌더링을 확인했으며 수집된 콘솔 오류는 없었어요.

이 브라우저 도구는 수정 키를 누른 상태의 드래그를 지원하지 않아 Alt + 드래그는 포인터 이벤트 회귀 테스트로 검증했어요. 실제 확장 재로드와 네이티브 플레이어 위의 Alt + 드래그는 미검증이에요. 확장을 다시 로드하고 라이브 탭을 새로고침한 뒤, 구분선을 움직여 여백을 만들고 메인·보조 영상에서 Alt + 드래그 → 왼쪽 버튼을 누른 채 우클릭 취소 → 다시 드래그 후 놓기를 확인하면 돼요.

### 드래그 중 우클릭 취소 — 2026-09-06

## 설정 목록에서 방송 이동과 메인 교체 — 2026-09-06

설정 목록의 첫 행에 메인을 고정하고 그 아래에 현재 화면 순서대로 서브 방송을 나열해요. 방송 행의 이름·여백을 잡아 드래그하면 놓일 위치를 선이나 메인 교체 테두리로 안내해요. 서브끼리 이동할 때는 화면의 기존 분할 크기를 유지하면서 목록 순서에 맞게 방송을 옮겨요. 공간 순서와 분할 트리 순서가 다른 경우에도 화면에서 보이는 순서가 기준이에요. 볼륨·음소거는 자리에 남고 저장 딜레이는 채널을 따라가요. 메인 행에는 제거·딜레이 조작을 추가하지 않았어요.

서브를 메인 행에 놓거나 메인을 서브 행에 놓으면 기존 `betterchzzk:multiview-navigate` 브리지로 치지직 내부 방송 이동을 요청해요. 승인되지 않은 이동은 기존 상태를 유지하고 실패를 표시해요. 해당 요청의 출발·도착 채널과 세대가 일치하는 라우트 전환에만 팝업을 복구하고 이동한 방송의 버튼으로 초점을 돌려요. 기존 메인은 서브 자리를 차지하며 보조 방송 정렬 버튼도 새 배치에서 계속 사용할 수 있어요.
